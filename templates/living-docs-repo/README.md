# <Project> — the living documents

Private repository. **Only project lead (PL) sessions write to it.** The dev has no access to it: they read the code
repository, `<owner>/<Project>-App`.

| path | holds |
|---|---|
| `Method/METHOD_<P>.md` | the project's method (takes precedence over the `methode-cdp` skill) |
| `<Folder>/CHECKPOINT_<P>.md` | the current state, entry point of each PL session |
| `<Folder>/DECISION_LOG_<P>.md` | the decisions, numbered D1, D2… |
| `<Folder>/PLAN_<P>.md` | the roadmap and the version log |
| `<Folder>/workstreams.yaml` | the single source of the workstreams |
| `<Folder>/workstreams.html` | ⟨extension: published board⟩ the readable page, **fixed** (about 11 KB, no workstream data), regenerated by `make_board.py` at each write of the yaml |
| `<Folder>/workstreams.json` | ⟨extension: published board⟩ **the data file** of the page, written by the same script next to it (same name): only the open workstreams, in short fields, **a data file small enough to be read in full** (method §6) |
| `<Folder>/archive_workstreams.py` | dates the accepted workstreams and moves out to `<Folder>/Archives/` those accepted for the delay of the method §6; `search` finds a workstream, living or archived; `normalize` puts the `.yaml` files in strict YAML format |
| `<Folder>/check_living_docs.py` | ⟨several PLs⟩ the read-only check of the shared living docs (twelve checks, among them 11: the `.yaml` files are valid YAML); with `--domains`, check 9 cross-checks each checkpoint's queue with `workstreams.yaml` |
| `Method/domains.yaml` | ⟨several PLs⟩ the domain table that check 9 reads: per domain, its PL, its checkpoint, the title of its queue section, its modules; kept by the coordinator in step with the method's table §1a |
| `<Folder>/expected/<version>/` | the acceptance expected results, computed at the brief — never read by the dev |
| `<Folder>/pl_tools/` | the PL's throwaway scripts (probes, measurements) and `context.py`, the context measure (thresholds: method §6) |
| `<Folder>/Archives/` | the frozen archives of living docs that grew long, including `WORKSTREAMS_<YYYY-MM>.yaml` (written by the archiving: things are only appended to it, frozen at the end of the month) |
| `<Folder>/arbiter.py`, `.github/workflows/arbiter.yml`, `Method/ARBITER.md`, `Method/ARBITER_LOG.md` | ⟨optional, several PLs⟩ the living-docs arbiter: a daily **GitHub Action**, with no session (the script, its workflow, what it does and does not do, its log of one line per run); it fails when it has filed a workstream, and GitHub's e-mail warns |
| `Method/CONTROLLER.md`, `Method/CONTROLLER_LOG.md` | ⟨optional, several PLs⟩ the controller: a weekly Opus session, by scheduled task, that judges the form of the documents (contradiction, omission, duplicate, useless history) and returns at most five findings as workstreams; its log, one line per Monday |

**Rules**: stable names (the version is in the header, the history in git); `git pull` before writing; a commit
“Batch v<X.Y> closed” at each close-out, with the line `Context: <N> tokens, of which <F> of fixed load` (method §6) ⟨; with the mirror extension,
the claude.ai project holds a mirror of it, copied over by the PL from their clone⟩.

⟨extension: published board — **The workstreams board has a single link**: ⟨the artifact's link⟩. Any other workstreams
page is obsolete; a trial page is deleted, with the owner's agreement.⟩

**Check, search**: the checker is run with `--archives` and, when several PLs each keep a checkpoint, with `--domains`
(check 9; `--root <folder>` if it is run from somewhere other than the repository root); a workstream that is no longer
in `workstreams.yaml` is looked for with `search` (`--everywhere`: in all the values); the arbiter workflow's variable
`LOG_FROM` is the number of the first decision log entry written after the installation (check 12 measures only those; empty,
the log is not measured):
```
python3 -B <Folder>/check_living_docs.py --workstreams <Folder>/workstreams.yaml \
  --log <Folder>/DECISION_LOG_<P>.md ⟨--board <Folder>/workstreams.html \
  --generator <Folder>/make_board.py⟩ --plan <Folder>/PLAN_<P>.md --archives <Folder>/Archives \
  --domains Method/domains.yaml
python3 -B <Folder>/archive_workstreams.py search <id or word> --workstreams <Folder>/workstreams.yaml \
  --archives <Folder>/Archives
```

⟨extension: published board — **Republishing the board** — **at close only**, not at each write of the yaml (the fixed page and its data file, at the
same link):
1. **regenerate after the last `git pull` / rebase, never before** (a real case: a data file pulled before the base
   missed three workstreams of another session; check 6 saw it); the checker passes, **check 6 OK** — it is what
   guarantees the data, not a reading;
2. **the PL reads, themselves and in full, the page and the data file** — the artifact tool requires it for any file the
   session did not write, **including the already-published data file being replaced**; a reading “by file” does not
   count;
3. **they re-read the diff of their own writes** in `workstreams.yaml` since their last publication;
4. **they republish the page and the data file together**, at the same link, even if only the data changed.
A page opened from the disk does not load its data: it is served (`python3 -m http.server` in the folder) or published.⟩

**Never here**: secrets, production data, images.

**Resuming a domain**: the owner pastes, in a new conversation of the project with Opus, the domain's fixed line —
nothing to upload. **It names all the domain's repositories**: a session's safeguard refuses an attachment the owner
has not asked for in so many words; the pasted line stands for that request. One more repository along the way: the
session asks the owner for it in a ready line (“tell me “attach X””).
